# 증권 데스크 MCP 시나리오집

MCP 서버 8종(도구 55개)을 연결한 Gemini Enterprise 어시스턴트로 **무엇을 물어볼
수 있는지**를 데스크별로 정리했습니다.

한 번의 조회로 끝나는 질문은 넣지 않았습니다. 여러 기관의 데이터를 엮고, 기준일을
맞추고, 계산까지 해야 답이 되는 실무 질문 13개를 골랐습니다.

- 서버 8 · 도구 55 · 스킬 11 · 시나리오 13
- 시스템 프롬프트는 [`SYSTEM_PROMPT.md`](./SYSTEM_PROMPT.md), 도메인 상세 규칙은
  [`../skills/`](../skills/)에 있습니다

---

## 이 도구가 잘하는 일

"삼성전자 어제 종가"는 어느 도구로도 답이 나옵니다. 이 구성이 값을 하는 지점은
따로 있습니다.

**여러 기관의 데이터를 하나의 답으로 엮습니다.**
회사채 스프레드는 금융위 채권 시세와 한국은행 국고채 금리를 함께 봐야 나옵니다.
예금 금리 흐름은 한국은행 거시 지표와 금감원 판매 금리가 다른 값이라는 것을 알아야
설명이 됩니다. 사람이 세 사이트를 오가며 하던 일을 한 번의 질문으로 처리합니다.

**계산 전에 식별자를 확정합니다.**
ISIN, 법인등록번호, 펀드 표준코드를 먼저 고정하고 조회합니다. 동명 종목이나
우선주가 섞여 답이 조용히 틀어지는 일을 막는 단계입니다.

**출처와 기준일이 항상 답에 붙습니다.**
금융 수치는 시점이 없으면 틀린 값입니다. 모든 답변에 `출처 · 기준일`이 남아
그대로 자료에 옮길 수 있습니다.

### 질문을 좁히면 답이 나옵니다

시세는 종목 단위로 조회합니다. **종목·발행사·기간을 지정한 질문**이 가장 빠르고
정확한 답을 받습니다.

| 이렇게 물으면 | 바로 답이 나옵니다 |
| --- | --- |
| 종목·발행사를 지정 | "포스코홀딩스 회사채 스프레드", "에코프로비엠 대차잔고" |
| 날짜·기간으로 필터 | "다음 달 배당 기준일이 오는 종목", "이번 분기 콜 행사 일정" |
| 조건으로 목록 조회 | "정기예금 금리 상위 은행", "국내 채권형 펀드 판매 상위" |

시장 전체를 훑어 계산하고 순위를 매기는 질문(예: "코스닥 전 종목 중 지수 대비 가장
부진한 종목")은 종목마다 시계열을 받아야 해서 대화 한 턴에 담기지 않습니다. 이때
어시스턴트는 **어떤 종목을 볼지 되묻고**, 지정해 주면 그대로 처리합니다.

# 시나리오

데스크별로 묶었습니다. 순서는 우선순위가 아닙니다.

각 시나리오의 **정확도의 조건**은 그 답이 왜 믿을 만한지를 설명합니다. 실무에서
답을 조용히 틀리게 만드는 지점들이고, 어시스턴트가 그것을 어떻게 처리하는지가
적혀 있습니다.

## 리서치 · 기업분석

### 크레딧 스프레드 비교 · 서버 3

> "포스코홀딩스와 LG화학 회사채의 최근 3개월 국고채 3년 대비 스프레드 추이를
> 비교해줘"

```
fsc-ficc   get_bond_basic              발행조건·잔존만기
fsc-ficc   get_bond_call_redemption    콜 조항 확인
fsc-market get_bond_price              개별 채권 수익률 시계열
ecos       search_statistic_tables  →  get_statistic_series   국고채 3년
```

**정확도의 조건**

- 잔존만기를 맞춰서 비교합니다. 만기가 다르면 스프레드가 아니라 기간 프리미엄을
  재게 됩니다.
- 콜 조항을 먼저 확인합니다. 옵션부 채권은 YTM이 아니라 YTC로 봐야 비교가
  성립합니다.
- 두 소스의 기준일을 각각 밝힙니다. 금융위 채권 시세와 한국은행 금리는 갱신 시점이
  다를 수 있습니다.

**답에 담기는 것** — 종목별 스프레드 추이 표, 콜 조항 유무, 두 소스의 기준일,
스프레드가 계산값이라는 표시.

### 재무 추이와 공시 원문을 한 번에 · 서버 2

> "한화오션 3년치 부채비율 추이를 뽑고, 최근 유상증자 결정 공시가 있었는지
> 확인해서 있으면 원문도 같이 보여줘"

```
fsc-research get_corp_outline           crno(법인등록번호) 확정
fsc-research get_financial_statement    bizYear 3개 연도
dart         resolve_company         →  search_dart_apis("유상증자")  →  call_dart_api
```

**정확도의 조건**

- 법인등록번호를 먼저 확정하고 조회해 동명 법인이 섞이지 않게 합니다.
- 계산은 금융위 정규화 재무제표로, 원문 인용은 DART로 역할을 나눕니다. 두 소스는
  계정 정의가 달라 한 표에 섞지 않습니다.
- 부채비율처럼 계산한 값은 산식과 함께 제시합니다.

**답에 담기는 것** — 3개 연도 부채비율과 산식, 증자 공시의 발행 규모·목적·희석률,
공시 원문 링크.

### 그룹 지배구조 맵 · 서버 2

> "카카오 계열사 중 상장사만 골라서 최근 실적과 배당 이력을 정리해줘"

```
fsc-research get_affiliates          계열회사 목록
fsc-market   find_listed_item        상장 여부·ISIN 확정
fsc-research get_financial_statement
fsc-research get_disclosure          배당 공시
```

**정확도의 조건**

- 계열사 법인명을 종목 마스터와 대조합니다. 법인명과 상장 종목명이 다른 경우가
  흔합니다.
- 상장사와 비상장사를 나눠서 표시합니다. 비상장은 시세가 없으므로 빈칸이 아니라
  "비상장"으로 남깁니다.

**답에 담기는 것** — 상장/비상장을 나눈 계열사 표, 각 행의 ISIN, 배당 기준일과 주당
금액.

## FICC · 자금

### 조달-운용 스프레드 · 서버 3

> "REPO 조달금리와 CP 91일물 매매금리 스프레드가 기준금리 인하 이후 어떻게
> 움직였어?"

```
fsc-equity-ops get_repo_rate          담보 종류별
fsc-ficc       get_short_term_rate    CP·CD 실거래
ecos           get_statistic_series   기준금리
```

**정확도의 조건**

- REPO 금리는 담보 종류를 구분해서 비교합니다. 담보별로 금리가 갈리므로 뭉뚱그리면
  스프레드가 달라집니다.
- CP·CD는 발행이 아니라 **실거래** 기준이라 체감 조달금리에 가깝습니다.
- "인하 이후"의 시작점은 한국은행 기준금리 시계열에서 확정합니다.

**답에 담기는 것** — 담보 구분을 유지한 스프레드 추이, 인하 결정일로 나눈 구간 비교.

### 콜 리스크 캘린더 · 서버 2

> "포스코홀딩스·롯데케미칼·SK하이닉스가 발행한 채권 중 다음 두 분기 안에 콜 행사
> 가능한 건이 있는지 보고, 있으면 재투자 대안 수익률도 정리해줘"

```
fsc-ficc get_bond_call_redemption
fsc-ficc get_bond_right_schedule    이자지급·상환일
fsc-ficc get_retail_bond_yield      재투자 대안
ecos     get_statistic_series       국고채 커브
```

**정확도의 조건**

- 콜 "가능"과 콜 "행사"를 구분해서 씁니다. 행사 여부는 발행사 결정이므로 단정하지
  않습니다.
- 이자지급일과 콜 행사일이 겹치는 구조가 있어 권리일정을 따로 확인합니다.
- 발행사나 ISIN으로 범위를 좁혀 물으면 바로 처리됩니다. 보유 포지션으로 좁히려면
  종목 리스트를 대화에 붙여넣으면 됩니다.

**답에 담기는 것** — 월별 캘린더, 종목별 콜 조건, 재투자 후보와 그 선정 기준.

## 트레이딩 · 시황

### 초과수익률과 수급을 함께 · 서버 2

> "에코프로비엠·HLB·알테오젠, 최근 한 달 코스닥 지수 대비 얼마나 언더퍼폼했고
> 대차잔고는 같이 늘었어?"

```
fsc-market     find_listed_item     시장구분(코스닥) 확인
fsc-market     get_stock_price
fsc-market     get_market_index     idxCsf = KOSDAQ 계열
fsc-equity-ops get_stock_lending    대차 현황
```

**정확도의 조건**

- 코스닥 종목은 코스닥 계열 지수와 비교합니다. 벤치마크를 잘못 잡으면 초과수익률이
  통째로 달라집니다.
- 대차잔고는 공매도 압력의 대리지표이며 공매도 자체가 아니라는 점을 답변에
  밝힙니다.
- 휴장일과 액면분할을 반영해 수익률을 계산합니다.

**답에 담기는 것** — 종목별 초과수익률(종목 − 계열지수), 같은 기간 대차잔고 변화,
둘의 관계가 정황이지 인과가 아니라는 단서.

### 상품군이 갈리는 질문 · 서버 1

> "KODEX 골드선물(H) 수익률이 실제 금 시세 흐름과 얼마나 벌어졌어?"

```
fsc-market search_apis("금")  →  call_api    일반상품(금) 시세
fsc-market get_etf_price
```

**정확도의 조건**

- ETF는 전용 도구로 조회합니다. 주식시세 API에는 ETF가 없어 상품군에 맞는 도구를
  고르는 것이 첫 단계입니다.
- 기초자산과 ETF를 같은 기간·같은 기준일로 정규화해 비교합니다.
- 환헤지 여부는 이 데이터에 없으므로 괴리의 원인으로 단정하지 않습니다.

**답에 담기는 것** — 기준 100으로 정규화한 두 시계열, 괴리 폭, 설명되지 않는 잔차를
잔차로 남긴 기술.

## 오퍼레이션 · 권리·대차

### 실물 주권 입고 심사 · 서버 2

> "고객이 삼성전자 실물 주권 입고를 요청했다. 처리해도 되나?"

```
fsc-market     find_listed_item        ISIN 확정
fsc-equity-ops check_irregular_stock   사고주권 여부
fsc-equity-ops get_right_schedule      명의개서 정지·권리 일정
```

**정확도의 조건**

- **조회 성공과 조회 실패를 명확히 구분해서 보고합니다.** 결과 0건은 "등록 내역
  없음", 조회 실패는 "확인하지 못함"입니다. 업무 판단의 근거가 되는 조회이므로 이
  구분이 가장 중요합니다.
- ISIN을 먼저 고정해 동명 종목·우선주 오인을 막습니다.
- 최종 판단은 담당자가 한다는 문장을 답변에 남깁니다.

**답에 담기는 것** — 항목별 조회 결과와 기준일, "조회 결과 등록 내역 없음 · 기준일
YYYY-MM-DD" 형식의 명시적 표현, 담당자 확인 안내.

> 이 시나리오는 어시스턴트가 **모르는 것을 모른다고 말하는지**를 확인하기에 가장
> 좋습니다. 도입 검토 시 우선 확인해 보시길 권합니다.

### 배당 캘린더와 고객 안내문 · 서버 3

> "다음 달 배당 기준일이 오는 종목으로 고객 안내문 초안 만들어줘"

```
fsc-equity-ops get_dividend       기준일·주당 금액
fsc-market     get_stock_price    배당수익률 계산
fsc-research   get_disclosure     배당 공시 교차확인
```

**정확도의 조건**

- 배당 정보를 공시로 교차확인합니다. 기준일은 고객 안내에 그대로 나가는 값입니다.
- 배당수익률은 계산값이며 주가 기준일을 함께 적습니다.
- 특정 종목 보유 고객만 추리려면 종목 리스트를 함께 주시면 그 범위로 처리합니다.
  보유 현황 자체는 사내 시스템에 있습니다.

**답에 담기는 것** — 기준일 순 배당 캘린더, 주당 금액과 배당수익률, 그대로 고객에게
보여도 되는 수준의 안내 문구.

## 상품 · WM

### IRP 라인업 후보 · 서버 1

> "IRP 원리금비보장 라인업에 넣을 국내 채권형 펀드 후보를 추려줘"

```
fsc-industry get_fund_code                       펀드 표준코드
fsc-industry get_fund_sales                      판매기관·규모
fsc-industry search_apis("퇴직연금")  →  call_api
```

**정확도의 조건**

- 펀드 표준코드로 고정해 클래스(A/C/S)가 섞이지 않게 합니다.
- 판매 규모와 성과를 구분해서 제시합니다. 규모 순위가 곧 우열은 아닙니다.
- 선정 기준을 먼저 밝히고 그 기준으로 정렬합니다. 후보와 기준까지 제시하고 최종
  결정은 상품위원회에 남깁니다.

**답에 담기는 것** — 선정 기준, 기준별 정렬한 후보 목록, 클래스와 보수 구조.

### 거시 지표에서 상품 금리로 · 서버 2

> "기준금리 인하 이후 은행 정기예금 금리가 실제로 얼마나 내려왔어?"

```
ecos    search_statistic_tables  →  get_statistic_series   기준금리·수신금리
finlife search_deposit_products                            회사별 실제 판매 금리
```

**정확도의 조건**

- 한국은행 수신금리(가중평균)와 금감원 판매금리(현재 판매 중)는 서로 다른 지표라
  각각의 정의를 붙여 나란히 제시합니다.
- 금리는 기본금리·최고우대금리·우대조건을 함께 제시합니다. 우대조건 없는 금리
  안내는 그 자체로 틀린 안내입니다.
- 통계표 코드는 검색으로 확정하고 조회합니다.

**답에 담기는 것** — 거시 금리와 판매 금리를 나란히 놓은 추이, 회사별 기본/최고우대/
우대조건 3열 표.

## 경영관리 · 전략

### 수수료 경쟁 포지션 · 서버 1

> "온라인 주식거래 수수료를 우리와 미래에셋증권·한국투자증권·NH투자증권·KB증권·
> 키움증권 기준으로 거래금액 구간별 비교해줘"

```
fsc-industry get_brokerage_fee          수수료 공시
fsc-industry get_securities_firm_stats  basYm 필수
```

**정확도의 조건**

- 거래금액 구간을 맞춰서 비교합니다. 구간이 다르면 비교 자체가 성립하지 않습니다.
- 회사명 표기가 API마다 다릅니다(수수료 공시는 `삼성증권`, 경영통계는
  `삼성증권(주)`). 결과의 회사명 필드를 확인해 의도한 회사가 맞는지 검증한 뒤
  답합니다.
- 자사가 불리한 구간도 같은 기준으로 함께 제시합니다. 사내 자료라도 그대로 고객
  응대에 쓰일 수 있다는 전제로 작성합니다.

**답에 담기는 것** — 구간별 수수료 비교표, 유관기관 제비용 포함 여부, 비교 모집단의
정의.

> "올해 업계 ELS 발행 규모에서 우리 순위와 기초자산 쏠림을 보여줘"

**답에 담기는 것** — 발행 규모 순위표, 기초자산 분포(지수형/종목형) 비중, 쏠림
수치와 그 해석 기준.

# 금융권을 위한 안전장치

금융 도메인에서는 도구가 잘 도는 것만큼 **답할 수 없는 질문에서의 행동**이
중요합니다. 아래 동작이 기본으로 들어가 있습니다.

| 상황 | 어시스턴트의 동작 |
|---|---|
| 투자권유 요청 — "삼성전자 지금 사도 될까?" | 조회한 사실과 판단 기준을 제시하고, 매수·매도 권유나 목표주가 단정은 하지 않습니다. |
| 편향된 비교 요청 — "우리가 1위인 지표만 골라줘" | 같은 기준으로 유불리를 함께 제시합니다. 사내 자료도 대고객 자료로 나갈 수 있다는 전제로 작성합니다. |
| 개인정보가 섞인 질의 — 계좌번호·주민등록번호 포함 | 식별정보를 도구 인자나 답변에 옮기지 않고, 필요한 최소 정보로 처리합니다. |
| 데이터가 아직 없는 시점 — 장중에 "오늘 종가" | 확정 시세 갱신 시점을 안내하고 최근 영업일 기준으로 조회합니다. 값을 추정해 채우지 않습니다. |
| 범위 밖 질의 — 해외 종목·해외 공시 | 다루는 범위를 밝히고, 웹 검색 결과로 대충 메우지 않습니다. |
| 조회 실패 | 실패를 실패로 보고합니다. 특히 사고주권·배당 기준일은 실패를 "해당 없음"으로 답하지 않습니다. |

원금 손실이 가능한 상품을 다룬 답변에는 투자권유가 아니라는 안내가 자동으로
붙습니다.

# 데이터 범위

이 구성이 다루는 것과 별도 연동이 필요한 것을 미리 정리했습니다.

**다루는 것** — 국내 상장 종목의 일별 확정시세, 채권 발행조건과 실거래 금리, 기업
재무제표와 전자공시, 배당·권리·대차, 펀드와 증권업계 통계, 거시경제 시계열, 금융상품
판매 금리. 모두 공개된 공공데이터이며 조회 전용입니다.

**별도 연동이 필요한 것**

| | 현재 | 연동하면 |
|---|---|---|
| 장중 실시간 시세·호가 | 기준일 다음 영업일 13시 이후 확정 시세 | 실시간 시세 벤더 연동 |
| 고객 계좌·보유·거래내역 | 없음 (종목 리스트를 주면 그 범위로 처리) | 사내 계정계 연동 |
| 내부 리서치·목표주가 | 없음 | 사내 리서치 DB 연동 |
| 해외 종목·해외 공시 | 없음 (국내 전용) | 해외 데이터 소스 추가 |

MCP 서버를 추가하는 방식이라 위 항목들은 같은 구조로 확장할 수 있습니다.
어시스턴트 쪽 변경 없이 서버만 붙으면 됩니다.

일부 공공데이터 API는 활용신청 승인이 필요합니다. 미승인 API는 조회가 막히며,
어시스턴트는 이를 데이터 없음이 아니라 권한 문제로 구분해 보고합니다.

# 시연 순서

난이도순이 아니라 **신뢰가 쌓이는 순서**입니다.

1. **단일 서버로 기준일 개념을 먼저 보여줍니다.**
   "삼성전자 지난달 종가 추이" — 한 번에 답이 나오되, 출처와 기준일이 답에
   따라붙는 형태를 확인합니다.
2. **두 기관의 데이터를 잇습니다.**
   예금 금리 시나리오. 한국은행 거시 지표와 금감원 판매 금리가 다른 값이라는 것을
   설명하는지 봅니다.
3. **세 서버로 계산까지 갑니다.**
   크레딧 스프레드 시나리오. 잔존만기를 맞추고 두 소스의 기준일을 밝히는지
   확인합니다.
4. **모르는 것을 확인합니다.**
   사고주권 조회. 조회 성공과 실패를 구분해 보고하는지가 이 단계의 관전
   포인트입니다.
5. **안전장치를 확인합니다.**
   투자권유 요청과 편향 비교 요청. 거절에서 끝나지 않고 할 수 있는 일을
   제시하는지까지 봅니다.

특성(상장·비상장 혼재, 코스닥 소속, ETF와 기초자산 분리 같은 것)을 드러내기 좋아서
골랐습니다. 실제 시연에서는 그날 다루는 종목으로 바꿔 쓰시면 됩니다.

본 문서의 시나리오는 정보 제공 목적이며 투자권유가 아닙니다.
