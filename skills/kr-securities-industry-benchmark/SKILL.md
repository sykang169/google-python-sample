# 금융투자업계 상품·경쟁사 분석

자사와 경쟁사를 **같은 잣대로** 비교하는 데이터다. 비교 기준을 어떻게 잡느냐가
결론을 바꾸므로, 이 스킬의 규칙은 대부분 "공정하게 비교하는 법"이다.

## 핵심 규칙

> [!IMPORTANT]
> 경쟁사 비교에서 가장 흔한 사고는 데이터 오류가 아니라 **비교 설계의 편향**이다.

1. **지표를 골라 결론을 만들지 않는다.** 특정 회사가 유리해 보이는 지표만
   제시하는 것은 분석이 아니다. 자사가 불리한 지표도 같이 싣는다.
2. **규모를 통제한다.** 대형사와 중소형사의 절대 금액을 나란히 놓으면
   당연히 대형사가 크다. 순위를 매길 때는 자기자본 대비, 계좌당, 점유율처럼
   정규화한 값을 함께 보여 준다.
3. **기준월(`basDt` / `basYm`)을 맞춘다.** 회사마다 제출 시점이 달라 최신
   데이터의 기준월이 섞일 수 있다. 다른 달의 값을 나란히 비교하지 않는다.
4. **회사명 표기가 흔들린다.** "(주)"·"증권"·"투자증권"이 붙고 빠진다.
   `likeCmpyNm`류 부분 일치로 찾고, 매칭한 실제 표기를 답변에 남긴다.

## 도구별 쓰임

| 도구 | 언제 |
| --- | --- |
| `get_fund_code` | 펀드 표준코드. 상품 마스터 |
| `get_fund_sales` | 펀드 판매현황. 판매기관·고객유형·펀드유형별 |
| `get_securities_firm_stats` | 증권사 일반현황(임직원 등) |
| `get_brokerage_fee` | 증권사 주식거래 수수료 공시 |
| `get_kofia_stat` | 금투협 CMA 통계 |

금투협 종합통계에는 CMA 외에 **ELS/ELB, DLS/DLB, 펀드 순자산, 신용공여
잔고, 신탁 규모, 시가총액, 파생상품 거래**가 함께 들어 있다.
`search_apis("ELS")`처럼 찾아 `call_api`로 실행한다.

## 수수료를 비교할 때

`get_brokerage_fee`는 `ctg`("변경후" 등)와 `trAmt`(거래금액 구간)로 나뉜다.

- **거래금액 구간을 맞춰야 비교가 성립한다.** 200만원 구간 수수료와
  1억원 구간 수수료를 나란히 놓으면 안 된다.
- 온라인/오프라인, 유관기관 제비용 포함 여부가 회사마다 다르다.
  단순 숫자 비교가 아니라는 점을 밝힌다.
- 공시 시점(`basDt`) 이후 변경되었을 수 있다.

## 펀드 판매현황

`get_fund_sales`는 판매**기관** 기준 집계다. 운용사 기준이 아니다.
`fundPtrnCd`(펀드 유형), `ivsAreaClsfCd`(투자지역)로 나뉘므로,
"점유율"을 말할 때 **어느 모집단의 점유율인지** 명시한다.
전체 대비인지, 주식형 안에서인지에 따라 순위가 뒤집힌다.

## 경영지표를 볼 때

증권사·자산운용사 통계는 `basYm`(기준월) 단위이고 과거가 길게 쌓여 있다.
필터 없이 조회하면 2001년 행이 먼저 나온다. 반드시 `basYm`을 건다.

폐업·합병된 회사가 과거 데이터에 남아 있다. 현재 존재하지 않는 회사를
"경쟁사"로 제시하지 않도록, 최근 기준월에도 나타나는지 확인한다.

## 도구를 고르는 순서

```
이름 있는 도구로 되는가?  →  그걸 쓴다
       ↓ 아니면
search_apis("검색어")     →  service · operation · fields 확인
       ↓
call_api(service, operation, params)
```

`search_apis`가 돌려주는 `fields`가 **그 오퍼레이션의 응답 필드이자 필터
파라미터**다. 금융위 API는 응답 필드명을 그대로 쿼리 파라미터로 받는다.
이 목록은 실제 호출로 수집한 것이라 문서와 어긋나지 않는다.

파라미터를 기억해서 쓰지 않는다. 필드명을 지어내면 조용히 무시되어
**필터가 걸리지 않은 전체 결과**가 돌아온다 — 오류가 아니라 잘못된 답이 된다.

## 자주 쓰는 필터

| 필드 | 뜻 |
| --- | --- |
| `basDt` | 기준일자 `YYYYMMDD` (하루) |
| `beginBasDt` / `endBasDt` | 기간 조회 |
| `itmsNm` / `likeItmsNm` | 종목명 정확 일치 / 부분 일치 |
| `isinCd` / `crno` | ISIN·법인등록번호 — 확정 방법은 [kr-entity-resolution](../kr-entity-resolution/SKILL.md) |
| `basYm` | 기준월 `YYYYMM` (통계 계열) |

## 오류 코드

금융위 API는 **HTTP 200과 함께** `resultCode`로 결과를 준다.

| 코드 | 뜻 | 대응 |
| --- | --- | --- |
| `03` | 데이터 없음 | 오류가 아니다. 휴장일·기간·필터를 확인해 재시도 |
| `12` | 서비스/오퍼레이션 없음 | 이름을 지어냈다는 신호. `search_apis`로 재확인 |
| `30` | 미승인 서비스키 | data.go.kr 활용신청이 필요하다. 재시도해도 소용없다 |
| `22` | 요청 제한 초과 | 잠시 후 재시도. 조회 횟수를 줄인다 |

> [!WARNING]
> **`12`를 미승인으로 읽지 않는다.** 미승인은 `30` 하나뿐이다.

## 상류가 막혔을 때

금융위 API는 짧은 시간에 호출이 몰리면 **소스 IP 단위로 접속을 수 분간 막는다.**
그때는 도구가 다음 형태로 답한다.

- `apis.data.go.kr에 연결하지 못했습니다` — 연결 자체가 막혔다
- `연결이 반복 실패해 N초 동안 호출을 멈춥니다` — 서버가 회로를 닫아 상류를 쉬게 하는 중

둘 다 **데이터가 없다는 뜻이 아니다.** 사용자에게 "지금 조회할 수 없다"고 알리고,
기억이나 웹 검색으로 수치를 채우지 않는다. 잠시 후 다시 시도하면 된다.

같은 조회를 반복하지 않는다. 서버가 응답을 캐시하므로 정상일 때는 반복 조회가
저렴하지만, 막힌 상태에서 재시도를 반복하면 차단이 길어진다.

## 시점을 반드시 밝힌다

> [!CAUTION]
> **이 데이터는 실시간이 아니다.** 금융위 제공 서비스는 기준일 다음 영업일
> 13시 이후에 갱신된다. 오늘 날짜로 조회해 데이터가 없는 것은 정상이다.

숫자를 인용할 때는 항상 **출처 · 기준일 · 단위**를 함께 쓴다.

휴장일 처리, "최근"을 구간으로 바꾸는 법, 기간 계산의 함정은
[kr-market-calendar](../kr-market-calendar/SKILL.md)에 있다.
값은 전부 문자열이므로 계산 전에 숫자로 바꾸고, 빈 문자열은 0이 아니라 결측이다.

## 하지 말아야 할 것

> [!CAUTION]
> 금융 수치를 사용자에게 내보내는 순간 규제 경계가 걸린다.
> [kr-financial-ai-compliance](../kr-financial-ai-compliance/SKILL.md)를 함께 읽는다.

- 조회에 실패했는데 그럴듯한 수치를 채워 넣지 않는다. 실패는 실패라고 말한다.
- 실시간인 것처럼 말하지 않는다. 기준일을 항상 명시한다.
- 데이터에 근거하지 않은 전망이나 매수/매도 의견을 덧붙이지 않는다.
