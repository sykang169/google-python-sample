# ECOS 거시경제 통계 분석

한국은행 ECOS는 국내 거시지표의 1차 출처다. 기준금리, 환율, 물가, 통화량,
국제수지, 자금순환이 모두 여기 있고 **약 840개의 통계표**로 나뉘어 있다.

## 핵심 규칙

> [!IMPORTANT]
> 이 API에서 나는 사고는 거의 전부 하나의 원인이다 — 코드를 기억에서 쓰는 것.

1. **`stat_code`를 절대 추측하지 않는다.** 통계표 코드는 외워서 쓰면 맞을 때보다
   틀릴 때가 많고, 틀려도 오류가 아니라 **다른 통계의 숫자**가 조용히 돌아온다.
   언제나 `search_statistic_tables`로 먼저 찾는다.
2. **`item_code1`을 생략하면 그 통계표의 모든 세부항목이 나온다.** 통계표에 따라
   세부항목이 수십 개이므로 항목 수 × 기간만큼 응답이 부푼다. 특정 계열만 필요하면
   `list_statistic_items`로 코드를 확인해 지정한다.
3. **`cycle`과 기간 형식이 어긋나면 데이터가 안 나온다.** 월 통계에 `20240101`을
   주면 `INFO-200`이다.

## 표준 워크플로

```
search_statistic_tables(stat_name="기준금리")   → stat_code 후보
      ↓
list_statistic_items(stat_code)                → item_code + 수록 기간(START_TIME/END_TIME)
      ↓
get_statistic_series(stat_code, cycle, start_period, end_period, item_code1)
```

빠른 개관만 필요하면 `list_key_statistics()`가 한국은행이 고른 100대 지표의
**최신값**을 한 번에 준다. 시계열이 아니라 스냅샷이라는 점에 주의한다.
"지금 기준금리 얼마야" 같은 단발 질문은 여기서 끝난다.

용어의 정의가 필요하면 `search_statistic_glossary("본원통화")`,
통계의 작성 기준·출처가 필요하면 `get_statistic_metadata("경제심리지수")`를 쓴다.

## 주기(cycle)와 기간 형식

`start_period` / `end_period`는 `cycle`에 정확히 맞춰야 한다.

| cycle | 주기 | 형식 | 예 |
| --- | --- | --- | --- |
| `A` | 연 | `YYYY` | `2020` |
| `S` | 반년 | `YYYYS1` | `2020S1` |
| `Q` | 분기 | `YYYYQ1` | `2020Q1` |
| `M` | 월 | `YYYYMM` | `202001` |
| `SM` | 반월 | `YYYYMMS1` | `202001S1` |
| `D` | 일 | `YYYYMMDD` | `20200101` |

모든 통계표가 모든 주기를 갖지는 않는다. GDP는 분기·연만, 환율은 일·월이 있다.
`list_statistic_items` 응답의 `CYCLE`, `START_TIME`, `END_TIME`, `DATA_CNT`로
**조회 전에** 가능한 주기와 수록 기간을 확인한다. 이 한 번의 호출이 대부분의
빈 응답을 예방한다.

## 통계표 찾기

`search_statistic_tables`의 검색은 통계표 **이름 부분 일치**다.

- `stat_name="환율"` → 이름에 "환율"이 든 표
- `stat_code=<코드>` → 코드를 이미 아는 경우 그 한 건만 (이름 검색보다 정확)
- `searchable_only=True`(기본) → 실제 시계열 조회가 가능한 표만.
  상위 분류까지 보려면 `False`

검색어가 너무 좁으면 0건이 나온다. "소비자물가상승률"보다 "소비자물가"가,
"원달러환율"보다 "환율"이 잘 걸린다. **넓게 찾아 후보를 본 뒤 고른다.**

통계표 코드는 이 문서에 적어 두지 않는다. 코드가 바뀌거나 잘못 옮겨 적히면
**오류 없이 다른 통계**를 조회하게 되므로, 매번 검색으로 얻는 편이 안전하다.

사용자의 표현("물가 올랐어?")을 한국은행 통계표 이름으로 옮기는 번역표와
검색이 0건일 때의 복구 절차는 [references/finding-tables.md](references/finding-tables.md)에 있다.
검색어를 두 번 바꿔도 안 걸리면 그 파일을 읽는다.

## 오류 코드 해석

ECOS도 **HTTP 200과 함께** `RESULT` 블록으로 오류를 준다.

| CODE | 뜻 | 대응 |
| --- | --- | --- |
| `INFO-200` | 조건에 맞는 데이터 없음 | 실패가 아니다. 기간을 넓히거나 `cycle`·`item_code`를 재확인 |
| `ERROR-400` | 검색범위 초과(60초 타임아웃) | 기간을 좁히거나 `end`를 줄인다 |
| `ERROR-100` | 필수값 누락 | 인자 확인 |
| `ERROR-602` | 과도한 호출로 이용 제한 | 잠시 후 재시도. 반복 조회를 줄인다 |

`INFO-200`을 그대로 "데이터가 없습니다"로 답하지 않는다. 대부분은 주기/기간
형식 불일치이거나 그 항목의 수록 기간을 벗어난 것이다. `list_statistic_items`로
한 번 확인하고 재시도한 뒤에 판단한다.

## 응답 해석

`rows`의 각 항목에서 실제로 쓰는 필드:

| 필드 | 뜻 |
| --- | --- |
| `TIME` | 시점. `cycle` 형식과 동일 |
| `DATA_VALUE` | 값. **문자열**이다 |
| `UNIT_NAME` | 단위 (%, 원, 십억원, 지수 …) |
| `ITEM_NAME1` | 세부항목 이름 |
| `STAT_NAME` | 통계표 이름 |

> [!WARNING]
> `UNIT_NAME`을 무시하면 답이 틀린다. 같은 표 안에서도 항목마다 단위가 다르고
> ("십억원" vs "원"), 지수는 기준연도가 있다(2020=100). 값을 인용할 때
> **단위와 기준연도를 함께** 쓴다.

`DATA_VALUE`는 문자열이므로 계산 전에 `float()`로 변환한다. 결측은 빈 문자열이나
`-`로 오며, 0으로 치환하면 추이가 왜곡된다 — 결측은 결측으로 남긴다.

## 지표 해석의 함정

- **물가지수 ≠ 물가상승률.** CPI는 지수다. 상승률이 필요하면 전년동월 대비로
  직접 계산하고(`(당월/전년동월 − 1) × 100`), 계산해서 얻은 값임을 밝힌다.
- **기준금리 변경은 계단식이다.** 월 평균으로 보면 인상 시점이 흐려진다.
  정책금리는 일별(`D`)로 보고 변경일을 짚는다.
- **환율은 매매기준율·종가 등 여러 계열이 있다.** 어느 계열인지 밝힌다.
- **명목 vs 실질**을 섞지 않는다. GDP·임금은 두 계열이 모두 있다.
- **속보치는 개정된다.** 최근 분기 GDP를 인용할 때는 "잠정/속보" 여부를 언급한다.

## 하지 말아야 할 것

- 거시지표로 **금리·환율 전망을 단정하지 않는다.** 과거 시계열의 설명과
  미래 예측은 다르며, 후자는 투자권유로 읽힐 수 있다
  ([kr-financial-ai-compliance](../kr-financial-ai-compliance/SKILL.md) 참고).
- 조회에 실패했을 때 기억 속 수치로 표를 채우지 않는다. ECOS 값은 개정되므로
  기억한 값은 대개 틀리다.
