# 금융상품 금리 비교 (FINLIFE)

금융회사가 **매월 금감원에 제출한 실제 판매 금리**다. 한국은행 기준금리 같은
거시 지표가 아니라 "지금 어느 은행에서 몇 %인가"에 답하는 데이터다.

## 핵심 규칙

> [!IMPORTANT]
> 금리 비교에서 나는 사고는 대부분 "숫자 하나만 보고 답한다"에서 온다.

1. **`intr_rate`(기본금리)와 `intr_rate2`(최고우대금리)를 구분한다.**
   최고우대금리는 `spcl_cnd`(우대조건)를 모두 충족했을 때의 값이다.
   우대조건을 빼고 "이 은행이 최고 4.5%"라고 답하면 사실상 틀린 안내다.
   **항상 두 값을 함께, 우대조건과 같이 제시한다.**
2. **권역을 하나만 보고 "제일 높다"고 말하지 않는다.** 기본값은 `은행`이다.
   저축은행 금리가 대개 더 높으므로, "가장 높은 금리"를 물으면
   최소한 `은행` + `저축은행`을 모두 조회한 뒤 비교한다.
3. **페이지를 끝까지 본다.** 응답의 `max_page_no`가 1보다 크면 나머지 페이지에
   더 높은 금리가 있을 수 있다. 1페이지만 보고 순위를 매기지 않는다.
4. **공시 기준월을 밝힌다.** 응답의 `disclosure_months`(YYYYMM)가 이 데이터의
   기준 시점이다. 실시간 금리가 아니며, 실제 적용 금리는 창구에서 달라진다.

## 상품군별 도구와 옵션 스키마

`options` 배열의 필드가 **상품군마다 완전히 다르다.** 그래서 도구가 나뉘어 있다.

| 도구 | 상품 | options의 핵심 필드 |
| --- | --- | --- |
| `search_deposit_products` | 정기예금 | `save_trm`(개월), `intr_rate`, `intr_rate2`, `intr_rate_type_nm`(단리/복리) |
| `search_savings_products` | 적금 | 위 + `rsrv_type_nm`(정액적립식/자유적립식) |
| `search_mortgage_loans` | 주택담보대출 | `mrtg_type_nm`(담보유형), `rpay_type_nm`(상환방식), `lend_rate_type_nm`(고정/변동), `lend_rate_min/max/avg` |
| `search_rent_house_loans` | 전세자금대출 | 위에서 `mrtg_type_nm` 제외 |
| `search_credit_loans` | 개인신용대출 | `crdt_grad_*`(신용점수 구간별 금리), `crdt_grad_avg` |
| `list_financial_companies` | 금융회사 | `area_nm`(영업지역) |

한 상품에 options가 여러 건 붙는다. 예금은 기간(6/12/24개월)별로, 주담대는
담보유형 × 상환방식 × 금리유형 조합별로 한 건씩이다.
**사용자 조건에 맞는 option 하나를 골라 비교해야 한다.** 12개월 예금을 묻는데
36개월 금리로 답하는 것이 가장 흔한 실수다.

## 금융권역

| 이름 | 코드 |
| --- | --- |
| 은행 | `020000` |
| 여신전문 | `030200` |
| 저축은행 | `030300` |
| 보험 | `050000` |
| 금융투자 | `060000` |

한글 이름을 그대로 넘기면 된다. 상품군에 따라 데이터가 있는 권역이 다르다 —
**정기예금·적금은 은행과 저축은행에만 있다.** 보험·금융투자 권역에 예금을
조회하면 빈 결과가 나오며, 이는 오류가 아니다.

회사 수(실측): 은행 18, 저축은행 80, 여신전문 48, 보험 20, 금융투자 7.

## 신용대출의 신용점수 구간

`crdt_grad_*` 필드명의 숫자는 등급이 아니라 **점수 구간**이다.

| 필드 | 신용점수 |
| --- | --- |
| `crdt_grad_1` | 900점 초과 |
| `crdt_grad_4` | 801~900점 |
| `crdt_grad_5` | 701~800점 |
| `crdt_grad_6` | 601~700점 |
| `crdt_grad_10` | 501~600점 |
| `crdt_grad_11` | 401~500점 |
| `crdt_grad_12` | 301~400점 |
| `crdt_grad_13` | 300점 이하 |
| `crdt_grad_avg` | 평균 금리 |

값이 `None`인 구간은 **그 회사가 해당 구간에 대출을 취급하지 않는다**는 뜻이다.
0%가 아니다. 사용자의 신용점수를 모르면 특정 구간의 금리를 단정하지 말고,
`crdt_grad_avg`와 구간 표를 함께 보여 준다.

## 상품 정보에서 놓치기 쉬운 필드

예금·적금:

| 필드 | 뜻 | 왜 중요한가 |
| --- | --- | --- |
| `spcl_cnd` | 우대조건 | `intr_rate2`를 받기 위한 조건. 급여이체·카드실적 등 |
| `join_deny` | 가입제한 | `1` 제한없음 / `2` 서민전용 / `3` 일부제한 |
| `join_way` | 가입방법 | 영업점/인터넷/스마트폰 |
| `max_limit` | 최고한도 | 한도가 작으면 고금리가 무의미하다 |
| `mtrt_int` | 만기 후 금리 | 방치하면 급락한다 |
| `etc_note` | 기타 유의사항 | |

대출:

| 필드 | 뜻 |
| --- | --- |
| `loan_inci_expn` | 대출 부대비용 (인지세·감정평가비 등) |
| `erly_rpay_fee` | 중도상환수수료 |
| `dly_rate` | 연체이자율 |
| `loan_lmt` | 대출한도 |

**금리만 비교하고 부대비용·중도상환수수료를 빼면 실질 비용 순위가 뒤집힌다.**
대출 비교에는 이 세 필드를 반드시 함께 싣는다.

필드 전체 용어 풀이는 [references/field-glossary.md](references/field-glossary.md)에 있다.

## 표준 워크플로

```
1. 사용자 조건 확정 — 상품군 / 기간 또는 상환방식 / 금액 / 권역
2. 해당 도구를 권역별로 호출 (은행 + 저축은행 최소 2회)
3. max_page_no까지 순회
4. 조건에 맞는 option만 골라 정렬
5. 기본금리 · 최고우대금리 · 우대조건 · 공시월을 한 표에
```

조건이 비어 있으면(기간을 안 밝힘 등) 임의로 정하지 말고 **가장 흔한 값으로
가정했다고 밝히거나** 되묻는다. 예금은 12개월, 주담대는 아파트·분할상환이
관행적 기본값이다.

## 답변 형식

```markdown
## [상품군] 금리 비교 — [조건]

**출처**: 금융감독원 금융상품통합비교공시 · 공시 기준월 YYYYMM · [권역]

| 금융회사 | 상품명 | 기본금리 | 최고우대금리 | 우대조건 요약 |
| --- | --- | --- | --- | --- |

### 유의사항
- 공시 금리이며 실제 적용 금리는 신용도·거래실적에 따라 달라집니다.
- (가입제한, 한도, 만기 후 금리 등 해당되는 것)
```

## 하지 말아야 할 것

> [!CAUTION]
> 금융상품 비교는 **금융소비자보호법의 판매 규제와 맞닿아 있다.**
> 상세는 [kr-financial-ai-compliance](../kr-financial-ai-compliance/SKILL.md)를 읽는다.

- **특정 상품을 "가입하세요"라고 권유하지 않는다.** 조건에 맞는 후보를
  비교 제시하고 판단은 사용자에게 남긴다.
- **불리한 정보를 빼지 않는다.** 최고우대금리만 강조하고 우대조건·한도·
  가입제한을 생략하는 것은 그 자체로 문제가 되는 안내다.
- 공시 금리를 확정 금리처럼 말하지 않는다.
- 데이터에 없는 상품(청약통장, 정책금융 등)을 있는 것처럼 답하지 않는다.
  펀드·퇴직연금·ISA는 FinLife가 아니라
  [kr-securities-industry-benchmark](../kr-securities-industry-benchmark/SKILL.md)에 있다.
