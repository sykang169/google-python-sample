# 국내 주식 시세 분석

금융위원회가 data.go.kr로 제공하는 **일자별 확정 시세**다. 실시간 호가가 아니라
장 마감 후 확정되는 일별 데이터이며, 이 차이가 답의 정확성을 좌우한다.

## 핵심 규칙

> [!IMPORTANT]
> 이 API는 잘못 물어도 **오류를 내지 않고 다른 답을 준다.** 그게 가장 위험하다.

1. **ETF는 이 서비스에 없다.** KODEX·TIGER·KBSTAR 같은 ETF는 `get_stock_price`
   에도 `get_fund_price`에도 수록되지 않는다. 비슷한 이름의 종목을 대신 내놓지 않는다.
   다만 **없는 데이터가 아니라 다른 서비스에 있는 데이터다** — 금융위원회
   `증권상품시세정보`(data.go.kr/data/15094806)가 ETF·ETN·ELW를 따로 제공한다.
   이 서버에는 아직 붙어 있지 않으므로, 요청받으면 "이 도구의 수록 범위 밖이며
   증권상품시세정보 API에 있다"고 알려 준다.
2. **`market`에 알 수 없는 값을 주면 조용히 무시된다.** `"NASDAQ"`을 넘기면
   오류 없이 **필터가 적용되지 않은 전체 결과**가 돌아온다. 조회 후 반환된
   `rows[].mrktCtg`를 실제로 확인한다. 허용값은 `KOSPI` / `KOSDAQ` / `KONEX`뿐이다.
3. **조건 없이 호출하지 않는다.** 종목도 기간도 안 주면 최신 일자부터 전체를
   훑는다. 종목(`item_name` 등)이나 기간(`base_date` / `begin_date`+`end_date`)을
   최소 하나는 지정한다.
4. **정확 일치와 부분 일치를 구분한다.** `item_name="삼성전자"`는 보통주만,
   `item_name_like="삼성전자"`는 `삼성전자우`까지 포함한다. 우선주가 섞이면
   수익률 계산이 오염된다.

## 도구 선택

| 도구 | 대상 | 비고 |
| --- | --- | --- |
| `get_stock_price` | 주식(주권) | 핵심 도구. KOSPI/KOSDAQ/KONEX |
| `get_fund_price` | 수익증권(공모펀드) | 자산운용사 공모펀드. 일자당 100건 미만 |
| `get_warrant_price` | 신주인수권**증권** (워런트) | 파생 성격 |
| `get_subscription_right_price` | 신주인수권**증서** | 유상증자 배정 청약권. 상장 기간 짧음 |

증권과 증서를 혼동하지 않는다 — 전혀 다른 상품이다.

## 종목 지정 방법

| 인자 | 의미 | 언제 |
| --- | --- | --- |
| `item_name` | 종목명 정확 일치 | 종목이 확정된 단일 종목 분석 |
| `item_name_like` | 종목명 부분 일치 | 종목명이 불확실하거나 계열 전체 |
| `isin_cd` | ISIN 12자리 (`KR7005930003`) | **가장 정확하다.** 반복 조회에 권장 |
| `short_code` | 단축코드 부분 일치 (`005930`) | 부분 일치임에 주의 |

종목명이 모호하면(동음 종목, 우선주, 스팩) 먼저 `item_name_like`로 좁은 기간
1일치만 조회해 후보와 `isinCd`를 확인하고, 이후 조회는 `isin_cd`로 고정한다.
이 습관 하나가 종목 오인을 대부분 막는다.

## 기간 조회

| 인자 | 형식 | 용도 |
| --- | --- | --- |
| `base_date` | `YYYYMMDD` | 특정 하루 |
| `begin_date` + `end_date` | `YYYYMMDD` | 기간 |
| `rows` | 정수 (최대 권장 100) | 페이지당 건수 |
| `page` | 정수 | 페이지 번호 |

> [!WARNING]
> **휴장일에는 데이터가 없다.** 주말·공휴일을 `base_date`로 주면 빈 결과가
> 나오고, 이는 오류가 아니다. "최근 종가"를 물으면 하루를 딱 집지 말고
> 최근 7~10일을 기간으로 조회해 **가장 최신 `basDt`의 행**을 쓴다.
> 데이터 반영에도 지연이 있으므로 오늘 날짜에 데이터가 없는 것도 정상이다.

기간이 길면 `rows` 기본값 20에 잘려 앞부분만 받게 된다. 영업일 수를 어림해
(1개월 ≈ 20영업일, 1년 ≈ 245영업일) `rows`를 넉넉히 주거나 `page`를 순회하고,
받은 행 수가 기대보다 적으면 **잘렸다고 의심한다.**

## 응답 필드

| 필드 | 뜻 | 단위 |
| --- | --- | --- |
| `basDt` | 기준일자 | `YYYYMMDD` |
| `srtnCd` | 단축코드 | |
| `isinCd` | ISIN | |
| `itmsNm` | 종목명 | |
| `mrktCtg` | 시장 구분 | KOSPI/KOSDAQ/KONEX |
| `clpr` | 종가 | 원 |
| `vs` | 전일 대비 | 원 |
| `fltRt` | 등락률 | % |
| `mkp` / `hipr` / `lopr` | 시가 / 고가 / 저가 | 원 |
| `trqu` | 거래량 | 주 |
| `trPrc` | 거래대금 | 원 |
| `lstgStCnt` | 상장주식수 | 주 |
| `mrktTotAmt` | 시가총액 | 원 |

값은 모두 **문자열**이다. 계산 전에 숫자로 변환하고, 빈 문자열은 0이 아니라
결측으로 다룬다.

## 오류 코드

data.go.kr은 HTTP 200과 함께 `resultCode`로 결과를 준다.

| 코드 | 뜻 | 대응 |
| --- | --- | --- |
| `03` | 데이터 없음 | 휴장일·종목명 오타·수록 범위 밖. 오류가 아니다 |
| `10` / `11` | 잘못된/누락된 파라미터 | 인자 형식 확인 |
| `22` | 요청 제한 초과 | 잠시 후 재시도. 조회 횟수를 줄인다 |
| `30` / `31` / `32` | 서비스키 문제 | 재시도해도 소용없다. 설정 문제로 보고 |

`apis.data.go.kr`은 앞단에서 **TCP 연결을 20분가량 거부했다가 조치 없이
자체 복구되는 구간**이 실제로 관측된다. 짧은 실패는 백오프 재시도로 넘어가지만,
반복 실패하면 종목이나 인자 문제가 아니라 상류 장애일 수 있다 — 그렇게 보고한다.

## 계산할 때의 함정

- **액면분할·병합**을 보정하지 않는다. 분할 전후 종가를 그대로 이어 수익률을
  계산하면 -80% 같은 값이 나온다. `lstgStCnt`가 특정 일자에 급변하면 신호다.
  의심되면 그 사실을 답변에 밝힌다.
- **우선주를 섞지 않는다.** `item_name_like` 결과에 `우`, `2우B` 등이 들어온다.
- **거래정지·관리종목**은 같은 종가가 반복된다. 변동성이 0에 가까우면 확인한다.
- **수익률**은 `(기말 종가 / 기초 종가 − 1) × 100`. 배당은 반영되지 않으므로
  총수익률이 아니라 **가격수익률**임을 밝힌다.
- **변동성**은 일간 로그수익률의 표준편차 × √245 (연율화). 표본 기간을 함께 쓴다.
- **시가총액**은 `mrktTotAmt`를 그대로 쓴다. `clpr × lstgStCnt`로 직접 계산하면
  우선주·자기주식 때문에 공시값과 어긋난다.

## 하지 말아야 할 것

> [!CAUTION]
> **시세 해석과 투자권유는 다르다.** 목표주가, 매수/매도 의견, "지금이
> 저점입니다" 같은 표현은 자본시장법상 투자권유로 읽힐 수 있다.
> 경계와 필수 고지는 [kr-financial-ai-compliance](../kr-financial-ai-compliance/SKILL.md)를 읽는다.

- 조회한 데이터에 없는 값을 기억으로 채우지 않는다. 주가는 기억으로 답하면 반드시 틀린다.
- 실시간 시세인 것처럼 말하지 않는다. 일별 확정 데이터이고 기준일을 항상 명시한다.
- ETF·해외주식·선물옵션을 이 API에서 찾지 않는다. 수록 범위 밖이라고 말하되,
  ETF/ETN/ELW는 증권상품시세정보, 선물·옵션은 파생상품시세정보에 있다고 알려 준다.
