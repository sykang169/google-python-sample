# 식별자 확정

**이름으로 조회하면 안 되는 이유는 실패해서가 아니라, 조용히 성공하기 때문이다.**
"삼성전자"로 조회했는데 우선주가 섞이거나, 동명 법인이 잡히거나, 필터가 무시된 채
전체 목록이 돌아와도 API는 오류를 내지 않는다.

계산은 코드를 확정한 다음에 시작한다.

## 핵심 규칙

1. **이름은 후보를 찾는 입력이고, 코드는 조회하는 열쇠다.** 둘을 섞지 않는다.
2. **한 번 확정한 코드로 이후 조회를 고정한다.** 매번 이름으로 다시 찾지 않는다.
3. **결과의 이름 필드를 눈으로 확인한다.** 의도한 대상이 맞는지 검증한 뒤 답한다.
4. **소스가 다르면 코드도 다르다.** 서로 변환되지 않으므로 각자 자기 소스에서
   확정한다.

## 식별자 다섯 가지

| 식별자 | 형태 | 쓰는 곳 | 확정 방법 |
| --- | --- | --- | --- |
| **ISIN** | 12자리 `KR7005930003` | 시세·채권·권리 계열 전반 | 상장종목 마스터 조회 |
| **단축코드** | 6자리 `005930` | 시세 계열 보조 | 상장종목 마스터 조회 |
| **법인등록번호** `crno` | 13자리 | 금융위 기업정보·재무제표 | 기업 개요 조회 |
| **corp_code** | 8자리 | DART 전자공시 전용 | DART 회사 조회 |
| **펀드 표준코드** | 펀드 상품 | 펀드·퇴직연금 계열 | 펀드 코드 조회 |

> [!IMPORTANT]
> **`crno`와 `corp_code`는 서로 변환되지 않는다.** 같은 회사라도 금융위 쪽은
> 법인등록번호로, DART 쪽은 자체 8자리 코드로 찾는다. 두 소스를 이어 붙이는
> 질문(재무 계산 + 공시 원문)에서는 **양쪽에서 각각 확정**해야 한다.

## 확정 순서

```
사용자가 준 이름
   ↓  부분 일치로 후보 조회
후보 목록 (이름 · 코드 · 시장구분)
   ↓  사람이 알아볼 수 있는 필드로 대상 확인
확정된 코드
   ↓  이후 모든 조회는 이 코드로
계산 · 답변
```

후보가 여럿이면 **임의로 첫 번째를 고르지 않는다.** 어느 쪽인지 되묻거나, 후보를
모두 제시하고 무엇을 골랐는지 밝힌다.

## 이름이 만드는 함정

### 우선주

`삼성전자`와 `삼성전자우`는 다른 종목이고 ISIN도 다르다. 종목명 부분 일치로
조회하면 **둘 다 잡힌다.** 수익률이나 시가총액을 계산하기 전에 어느 쪽인지 고정한다.

### 법인명과 종목명이 다르다

계열사 목록에서 받은 법인명이 상장 종목명과 다른 경우가 흔하다. 지주회사 전환,
사명 변경, 법인 형태 표기(`(주)`) 차이가 원인이다. **계열사 목록을 시세 조회로
넘길 때는 상장종목 마스터로 한 번 대조한다.**

### 같은 회사가 API마다 다르게 적힌다

실측 사례 — 증권사 통계와 수수료 공시가 같은 회사를 다르게 적는다.

```
경영통계   fncoNm  = 삼성증권(주)     ← 법인 형태 포함
수수료공시 cmpyNm  = 삼성증권         ← 괄호 없음
```

정확 일치 필터를 쓰면 한쪽에서만 걸린다. **회사명 필터는 소스마다 확인하고
쓴다.**

### 부분 일치 필터가 조용히 무시된다

실측 사례 — 증권사 통계에서 `likeFncoNm`은 오류 없이 **필터가 걸리지 않은 전체
결과**를 돌려준다.

> [!WARNING]
> 필터를 걸었다고 걸린 것이 아니다. **결과 행의 회사명·종목명 필드를 실제로 확인해
> 의도한 대상만 남았는지 검증한 뒤 답한다.** 이것을 건너뛰면 다른 회사의 숫자를
> 자사 수치로 제시하게 된다.

### 펀드는 클래스가 갈린다

같은 펀드도 A/C/S 클래스마다 표준코드와 보수가 다르다. 이름만으로 묶으면 서로 다른
상품의 수치를 섞게 된다. **표준코드로 고정한다.**

### 채권은 발행 회차가 다르다

같은 발행사도 회차마다 만기·표면금리·옵션 구조가 다르다. "포스코홀딩스 회사채"는
종목이 아니라 발행사이며, 스프레드나 수익률을 계산하려면 **개별 종목의 ISIN까지
내려가야 한다.**

## 비상장과 미수록

식별자를 확정할 수 없는 경우가 있고, 그것은 실패가 아니다.

- **비상장 법인**은 ISIN·단축코드가 없다. 재무제표는 조회되지만 시세는 없다.
- **계열사 목록에는 비상장이 섞여 있다.** 시세 열을 빈칸으로 두지 말고
  "비상장"으로 표시한다.
- **해외 법인**은 국내 소스에 없다. 확정할 수 없다고 말한다.

## 답변에 남길 것

식별자는 답의 근거다. 표나 인용에 함께 적는다.

```
삼성전자 (005930, KR7005930003, KOSPI)
한화오션 (crno 1101110xxxxxx)
DART 사업보고서 (corp_code, bsns_year, reprt_code)
```

여러 소스를 엮은 답이면 **어느 코드로 무엇을 조회했는지** 밝힌다. 나중에 숫자를
검증할 때 이 정보가 없으면 재현이 안 된다.

## 하지 말아야 할 것

- 코드를 기억에서 쓰지 않는다. ISIN·`corp_code`는 추측하면 **다른 회사**가 나온다.
- 후보가 여럿인데 하나를 골라 조용히 진행하지 않는다.
- 부분 일치 결과를 검증 없이 집계하지 않는다.
- `crno`와 `corp_code`를 서로 유추하지 않는다.
- 이름이 비슷하다는 이유로 다른 소스의 행을 같은 회사로 합치지 않는다.
- 확정하지 못한 대상을 "데이터 없음"으로 답하지 않는다. **식별 실패와 데이터
  없음은 다르다.**
