# 채권·단기자금 분석 (FICC)

국내 채권의 **발행조건과 실거래**를 다룬다. 한국은행 ECOS가 거시 금리 곡선이라면
이쪽은 개별 종목이다. 스프레드 질문은 **두 소스를 합쳐야** 답이 된다.

## 핵심 규칙

> [!IMPORTANT]
> 채권에서 나는 사고는 대부분 "금리 하나만 보고 답한다"에서 온다.

1. **표면금리(`bondSrfcInrt`)와 수익률은 다르다.** 표면금리는 발행 시 정해진
   이자율이고, 수익률은 현재 가격에서 계산된다. 둘을 섞으면 비교가 무의미해진다.
2. **스프레드는 만기를 맞춰야 한다.** "국고채 대비"라면 잔존만기가 비슷한
   국고채와 비교해야 한다. 3년물 회사채를 10년 국고채와 비교하면 숫자는 나오지만
   의미가 없다. 만기를 맞췄는지 답변에 밝힌다.
3. **옵션부채권은 만기가 만기가 아니다.** `get_bond_call_redemption`으로 콜
   내역을 확인한다. 콜이 예정된 채권의 만기수익률은 실현되지 않을 수 있다.
4. **거시 금리는 여기 없다.** 기준금리·국고채 시장금리는
   [ecos-macro-analysis](../ecos-macro-analysis/SKILL.md)다.

## 스프레드 워크플로

```
1. get_bond_basic(isinCd 또는 발행사)      → 발행조건·잔존만기 확인
2. ECOS get_statistic_series               → 같은 만기 국고채 금리
3. 스프레드 = 채권 수익률 − 국고채 금리
4. 만기를 맞췄음을 답변에 명시
```

**두 소스의 기준일이 다를 수 있다.** 금융위는 D+1, ECOS는 통계별로 다르다.
서로 다른 날짜의 값을 뺀 스프레드는 그렇다고 밝힌다.

## 도구별 쓰임

| 도구 | 언제 |
| --- | --- |
| `get_bond_basic` | 종목 식별의 출발점. 발행사·표면금리·만기·잔액 |
| `get_bond_principal_interest` | 원리금 구조. 캐시플로 산출 |
| `get_bond_right_schedule` | 이자지급·상환 일정. 이표채/할인채 구분(`bondIntTcdNm`) |
| `get_bond_call_redemption` | 옵션부채권 조기상환 내역 |
| `get_retail_bond_yield` | 소매채권 수익률. 신용등급(`crdtSc`)·기간(`ctg`)별 |
| `get_short_term_rate` | CP·CD 실거래 금액과 금리 |

그 밖의 채권 데이터(발행 통계, 만기별 현황 등)는 `search_apis("채권")`로 찾는다.

## 소매채권 수익률의 구조

`get_retail_bond_yield`는 개별 종목이 아니라 **구간별 요약**이다.

- `crdtSc` — 신용 구간 (예: "무위험")
- `ctg` — 잔존기간 구간 (예: "5년이상")
- `bnfRt` — 그 구간의 수익률(%)

개별 종목 수익률로 오해하지 않는다. 리테일 고객에게 "이 채권 몇 %"라고
답할 근거가 아니라, 구간 평균이다.

## CP·CD를 읽을 때

`get_short_term_rate`는 발행이 아니라 **매매(실거래)** 기준이다.
`shtrFinBzcDcdNm`으로 상품 종류(CP/CD/전자단기사채 등)를 거른다.
발행 정보가 필요하면 `search_apis("단기금융증권 발행")`으로 다른 서비스를 찾는다.

실거래 금리는 발행금리보다 시장 상황을 잘 반영하지만 **거래가 없는 날은
데이터가 없다.** `03`이 나오면 기간을 넓힌다.

## 도구를 고르는 순서

```
이름 있는 도구로 되는가?  →  그걸 쓴다
       ↓ 아니면
search_apis("검색어")     →  service · operation · fields 확인
       ↓
call_api(service, operation, params)
```

`search_apis`가 돌려주는 `fields`가 **그 오퍼레이션의 응답 필드이자 필터
파라미터**다. 금융위 API는 응답 필드명을 그대로 쿼리 파라미터로 받는다.
이 목록은 실제 호출로 수집한 것이라 문서와 어긋나지 않는다.

파라미터를 기억해서 쓰지 않는다. 필드명을 지어내면 조용히 무시되어
**필터가 걸리지 않은 전체 결과**가 돌아온다 — 오류가 아니라 잘못된 답이 된다.

## 자주 쓰는 필터

| 필드 | 뜻 |
| --- | --- |
| `basDt` | 기준일자 `YYYYMMDD` (하루) |
| `beginBasDt` / `endBasDt` | 기간 조회 |
| `itmsNm` / `likeItmsNm` | 종목명 정확 일치 / 부분 일치 |
| `isinCd` / `crno` | ISIN·법인등록번호 — 확정 방법은 [kr-entity-resolution](../kr-entity-resolution/SKILL.md) |
| `basYm` | 기준월 `YYYYMM` (통계 계열) |

## 오류 코드

금융위 API는 **HTTP 200과 함께** `resultCode`로 결과를 준다. 코드마다 다음에 무엇을
할지는 **도구가 오류 메시지에 함께 실어 보낸다.** 그 지침을 따르고, 코드를 "조회
실패"로 뭉뚱그리지 않는다 — `03`은 다시 물어야 하고 `30`은 재시도가 무의미하다.

## 상류가 막혔을 때

금융위 API는 짧은 시간에 호출이 몰리면 **소스 IP 단위로 접속을 수 분간 막는다.**
그때는 도구가 다음 형태로 답한다.

- `apis.data.go.kr에 연결하지 못했습니다` — 연결 자체가 막혔다
- `연결이 반복 실패해 N초 동안 호출을 멈춥니다` — 서버가 회로를 닫아 상류를 쉬게 하는 중

둘 다 **데이터가 없다는 뜻이 아니다.** 사용자에게 "지금 조회할 수 없다"고 알리고,
기억이나 웹 검색으로 수치를 채우지 않는다. 잠시 후 다시 시도하면 된다.

같은 조회를 반복하지 않는다. 서버가 응답을 캐시하므로 정상일 때는 반복 조회가
저렴하지만, 막힌 상태에서 재시도를 반복하면 차단이 길어진다.

## 시점을 반드시 밝힌다

> [!CAUTION]
> **이 데이터는 실시간이 아니다.** 금융위 제공 서비스는 기준일 다음 영업일
> 13시 이후에 갱신된다. 오늘 날짜로 조회해 데이터가 없는 것은 정상이다.

숫자를 인용할 때는 항상 **출처 · 기준일 · 단위**를 함께 쓴다.

휴장일 처리, "최근"을 구간으로 바꾸는 법, 기간 계산의 함정은
[kr-market-calendar](../kr-market-calendar/SKILL.md)에 있다.
값은 전부 문자열이므로 계산 전에 숫자로 바꾸고, 빈 문자열은 0이 아니라 결측이다.
